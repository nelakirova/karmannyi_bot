# Karmannyi Bot

Telegram-бот для продажи доступа в закрытые каналы «Карманный воспитатель».
Пользователь выбирает возраст ребёнка → срок доступа (1 месяц / 6 месяцев /
1 год) → вводит e-mail для чека → оплачивает через ЮKassa → бот
автоматически выдаёт персональную invite-ссылку в нужный канал.

Всего 12 курсов (4 возрастные группы × 3 срока), каждый — отдельный
Telegram-канал.

## Стек

- Go 1.25
- SQLite (файл `karmannyi.db`, без внешней БД)
- [go-telegram-bot-api/telegram-bot-api](https://github.com/go-telegram-bot-api/telegram-bot-api) v5
- ЮKassa REST API (`api.yookassa.ru/v3`)

## Как это работает

- Бот получает сообщения через **long polling** (не webhook) — постоянно
  подключён к Telegram и сам опрашивает обновления. Открытых входящих
  портов не требует.
- Проверка оплаты — тоже polling: раз в 10 секунд бот сам спрашивает у
  ЮKassa статус всех платежей, у которых ещё нет invite-ссылки
  (`checkPendingPayments` в `main.go`).
- База — один файл SQLite, миграции применяются автоматически при
  старте (см. `initDatabase` в `database.go`).

## Требования к серверу

- Linux (лучше Ubuntu 22.04/24.04), либо любая ОС, куда можно залить
  Go-бинарник — сборка кросс-компилируется под `linux/amd64`.
- Go нужен только для сборки — на сервере, где бот работает, Go
  устанавливать необязательно, если заливать готовый бинарник.
- Постоянный диск (для SQLite) — то есть подходит обычный VPS,
  serverless-платформы (Cloudflare Workers, Vercel и т.п.) **не подходят**:
  там нет файловой системы и нет долгоживущих процессов, а боту нужны
  оба.
- Исходящий доступ в интернет к `api.telegram.org` и `api.yookassa.ru`.
  Входящий доступ не нужен вообще (порт открывать не надо).

## Переменные окружения

Создай файл `.env` в корне проекта (пример — `.env.example`):

```
TELEGRAM_BOT_TOKEN=токен_от_BotFather
YOOKASSA_SHOP_ID=shopId_из_личного_кабинета_ЮKassa
YOOKASSA_SECRET_KEY=secretKey_из_личного_кабинета_ЮKassa

# Опционально. Нужно, только если сервер бота физически в России —
# см. раздел "Прокси" ниже.
TELEGRAM_PROXY_URL=
```

`.env` не должен попадать в git — он уже добавлен в `.gitignore`.

## Сборка и запуск

### Локально / для теста

```bash
go mod download
go run .
```

### Продакшн-сборка (бинарник под Linux)

```bash
GOOS=linux GOARCH=amd64 go build -o karmannyi-bot .
```

Получится один файл `karmannyi-bot` — заливай его на сервер вместе с
`.env` и (по желанию) существующим файлом `karmannyi.db`, если хочешь
сохранить историю заказов.

### Автозапуск через systemd

В репозитории есть готовый юнит `karmannyi-bot.service`. На сервере:

```bash
sudo cp karmannyi-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable karmannyi-bot
sudo systemctl start karmannyi-bot
```

Юнит ожидает, что бинарник и `.env` лежат в `/opt/karmannyi-bot/` — при
необходимости поправь пути в самом файле `.service` перед копированием.

Логи:

```bash
journalctl -u karmannyi-bot -f
```

## Структура проекта

| Файл | Что внутри |
|---|---|
| `main.go` | Точка входа, обработка сообщений/кнопок Telegram, сценарий покупки, фоновая проверка платежей |
| `database.go` | Всё для SQLite: схема, миграции, CRUD по заказам |
| `yookassa.go` | Создание и проверка платежей через API ЮKassa |
| `products.go` | Каталог из 12 курсов: цена, название, ID Telegram-канала для каждого |
| `karmannyi-bot.service` | systemd-юнит для автозапуска |
| `.env.example` | Шаблон переменных окружения |

## Каталог курсов (`products.go`)

Все 12 курсов и их каналы прописаны в `products.go` в массиве `products`.
Если нужно поменять цену, название или канал — правишь прямо там и
пересобираешь бинарник (Go компилирует исходники в бинарник, простого
редактирования на сервере без пересборки недостаточно).

Как узнать `ChannelID` нового/другого канала:
1. Добавь бота администратором в канал.
2. Перешли (forward) боту любое сообщение из этого канала.
3. В логах (`journalctl -u karmannyi-bot -f`) появится строка вида
   `ID канала: -100XXXXXXXXXX` — это и есть `ChannelID`.

## Важно про чек и e-mail

У этого магазина в ЮKassa включена обязательная фискализация чеков
(54-ФЗ) — API отказывается создавать платёж без данных для чека. Поэтому
бот **обязательно** собирает e-mail перед оплатой (шаг `awaitingEmail` в
`main.go`) и передаёт его в `receipt` при создании платежа
(`createYooKassaPayment` в `yookassa.go`).

Если на другом магазине ЮKassa фискализация не обязательна — можно
убрать шаг с e-mail и блок `receipt` из запроса, тогда пользователь сам
сможет запросить чек кнопкой «Получить квитанцию» на странице оплаты.
Но сначала стоит проверить это на тестовом платеже — при ошибке API
вернёт `"Receipt is missing or illegal"`.

## Прокси для Telegram (если сервер в России)

С начала 2026 года Роскомнадзор ограничивает доступ к Telegram на
территории России, что может влиять и на серверные подключения к
`api.telegram.org`. Если сервер бота физически в России, рекомендуется
завернуть только Telegram-трафик через недорогой прокси-сервер,
арендованный в другой стране (к ЮKassa это не относится — она
российская и доступна без ограничений).

1. Подними лёгкий HTTP-прокси (например, `tinyproxy`) на любом
   зарубежном VPS.
2. Впиши его в `.env`:
   ```
   TELEGRAM_PROXY_URL=http://логин:пароль@ip_прокси:порт
   ```
3. Если переменная не задана — бот работает как обычно, напрямую.

Логика — в функции `newTelegramBot` (`main.go`).

## Дополнительные команды бота

- `/start` — приветствие, кнопка «Получить доступ»
- `/buy` — сразу открыть выбор возраста
- `/status` — статус последнего заказа пользователя
- `/testlink <product_id>` — тестовое создание invite-ссылки для
  конкретного курса, без оплаты (например, `/testlink 8_10_1m`).
  Используй только для проверки, что бот — админ нужного канала.
  ID продуктов — в `products.go` (поле `ID`).
- `/help` — справка

## Обслуживание

- **Обновить код**: пересобери бинарник, залей поверх старого,
  `systemctl restart karmannyi-bot`.
- **Бэкап БД**: файл `karmannyi.db` в рабочей директории бота — копируй
  периодически.
- Все текстовые сообщения бота — в `main.go`, ищи по русским строкам.
